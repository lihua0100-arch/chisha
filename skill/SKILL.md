# 吃啥

只用这一个命令：`python3 /opt/data/tools/meal_plan.py <动作> [参数]`。
参数都是它自带的，**不要写 `python3 -c`、不要读它的源码**。

## 1. 用户问「吃啥」→ 查当天

| 用户说 | 命令 |
|---|---|
| 吃啥 / 今天吃什么 | `python3 /opt/data/tools/meal_plan.py today` |
| 明天吃啥 / 10月8号吃啥 | `... today --date 明天`（或 `--date 10-8`） |
| 中午/晚上吃啥 | 加 `--meal 午餐` 或 `--meal 晚餐` |
| 只要菜名 | 加 `--brief` |

把输出整理成好读的样子发给用户：菜名、用料、调料、做法步骤、最后的「今晚」提醒都要保留，
**不要删步骤、不要自己换菜或编菜**。输出末尾有「在线菜谱：<链接>」就把链接原样附在最后。

输出说「还没有生成过菜谱」或「不在当前菜谱里」：照实告诉用户，问他要不要做一份新的（要预算和时间）。

## 2. 做一份菜谱 → 生成 Excel

必须知道**预算**和**时间**。缺哪个就一句话把缺的一起问掉；口味没说就别问，直接做。

| 用户说 | 参数 |
|---|---|
| 500 块（总共） | `--budget 500` |
| 一周 200 / 每周 500 | `--budget 200 --per week` |
| 一天 30 | `--budget 30 --per day` |
| 一周 / 两周 / 10 天 | `--days 7` / `--days 14` / `--days 10` |
| 到月底 / 到 10 月 31 号 | `--until 10-31` |
| 从今天开始（默认是明天） | `--start 今天` |
| 一日三餐 / 要早饭 | `--meals 3`（默认 2 = 午饭+晚饭；只做晚饭 `--meals 1`） |
| 两个人吃 | `--people 2` |
| 爱吃牛肉、茄子 | `--like 牛肉,茄子` |
| 不吃香菜、鱼 | `--dislike 香菜,鱼` |
| 不吃辣 | `--no-spicy` |
| 家里有米油调料 | `--pantry` |
| 想换一批菜 | 同样参数再加 `--seed 2`（3、4……） |

例：「一周 500，爱吃牛肉不吃辣」→
`python3 /opt/data/tools/meal_plan.py plan --budget 500 --per week --days 7 --like 牛肉 --no-spicy`

跑完后：

1. 回复里**单独一行**写 `MEDIA:<输出第一行的文件路径>`，Excel 就会作为文件发过去。
2. 输出里有「在线菜谱（手机打开…）：<链接>」这一行，就把链接**原样**单独一行发给用户，
   说一句「手机点开就能看每天吃啥、做法和买菜清单」。链接每个号固定一个，重新生成菜谱后链接不变、内容自动更新。
3. 再用三五行说清：日期范围、每顿几个菜、总花费和结余、改善日几天、第一天吃什么、**今晚要解冻什么**。
   用户说了爱吃什么，就把输出里「爱吃的…排了 N 顿」那行照实转告（排在哪几天也说）。
4. 输出里 `⚠` 开头的行、「没匹配到」「注意」的行，**原意转告用户**——比如钱不够时工具会自己
   算出实际够几顿、只排那几顿、米油盐不算进来，你照实说「这些钱只够 N 顿」，别替用户硬凑满。
5. 输出说「连一顿饭都不够」、没有生成文件：照实告诉用户，不要发 MEDIA。

新生成的菜谱会替换掉旧的「当前菜谱」，之后问「吃啥」查的就是新的。

## 3. 要在线菜谱链接

用户说「菜谱链接」「发我网页版」「手机上看」：`python3 /opt/data/tools/meal_plan.py web`，把输出的链接原样发过去。
输出说还没有生成过菜谱：照第 2 节先问预算和时间。

## 4. 问菜价

`python3 /opt/data/tools/meal_plan.py prices`，只看几样加 `--item 猪肉,青菜`。
数据是上海市政府每个工作日发布的全市均价（60 多个菜场和超市实测），回复时带上日期和链接。

## 5. 能做哪些菜

`python3 /opt/data/tools/meal_plan.py dishes`（113 道，🌶 是辣的）。

## 边界

- 价格只有上海的；盒马、叮咚的价格以 App 为准。
- 菜库是固定的 113 道。用户想要库里没有的菜，就说要找管理员加。
- 每个微信号各存一份当前菜谱，互相看不到。
